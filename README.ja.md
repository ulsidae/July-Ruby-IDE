# 🌙 July Ruby IDE（日本語版）

<img src="https://github.com/ulsidae/July-Ruby-IDE/blob/main/img/img.jpg" height="400"/>

> コードがどのように実行されるのかを学び、試しながら理解するための軽量なRuby IDE。

🍯 [ダウンロード](https://github.com/ulsidae/July-Ruby-IDE/releases/tag/v2.0)

**July Ruby IDE** は、PythonとTkinterで構築した軽量なRuby開発環境です。

本格的なIDEと競合することを目的とせず、もっとシンプルなことに焦点を当てています。

> **Rubyを書く → 実行する → プロセスを観察する → 対話する**

エディタ、ローカルインタプリタ、対話型ターミナルがどのようにつながるのかを探るために作った実験的な学習プロジェクトです。

## ✨ 機能

### 📝 コードエディタ

* **Tkinter** で構築した軽量エディタ
* Rubyのシンタックスハイライト
* Undo対応
* エディタのフォントサイズ変更
* Tabによるインデント

### 💡 オートコンプリート

よく使われるRubyの構文やメソッドを対象とした基本的なオートコンプリート機能を搭載しています。

現在、以下のカテゴリをカバーしています。

* Rubyキーワード
* オブジェクト指向関連メソッド
* I/Oメソッド
* Enumerableメソッド
* Stringメソッド
* Arrayメソッド
* Hashメソッド
* Numericメソッド
* 型変換メソッド
* Proc / Lambdaメソッド
* その他のRubyメソッド

候補は以下の操作で確定できます。

* `Tab`
* `Enter`
* ダブルクリック

---

### ▶️ 対話型Ruby実行

Rubyコードは、システムにインストールされた**ローカルRubyインタプリタ**を使用して実行されます。

以下の機能を提供します。

* ▶ Run
* ■ Stop
* リアルタイム出力
* エラー出力
* 標準入力への対応
* プロセス終了ステータス

そのため、`gets` を使用するRubyプログラムにもIDEから直接入力できます。

```ruby
puts "What is your name?"

name = gets.chomp

puts "Hello, #{name}!"
```

---

### 💻 統合ターミナル

実行中のRubyプロセスと対話するための統合ターミナルを搭載しています。

以下の操作が可能です。

* プログラムの出力をリアルタイムで確認
* `stdin` への入力
* プロセスの状態を確認
* ターミナルのフォントサイズを変更

ターミナルは別ウィンドウに切り離すこともできます。

---

### 🪟 分離可能なターミナル

IDE内のターミナルを別ウィンドウで使いたい場合は、

**Detach Terminal**

をクリックします。

ターミナルは別ウィンドウで開きますが、同じRubyプロセスとの接続は維持されます。

後から、

**Attach Terminal**

をクリックすることでIDE内に戻すことができます。

---

### 📂 ファイル管理

Rubyソースファイルに対する基本的な操作に対応しています。

* `.rb` ファイルの保存
* `.rb` ファイルの読み込み
* ソースコードの編集と実行

## ⚙️ アーキテクチャ

July Ruby IDEは、実行パイプラインを意図的にシンプルにしています。

```
┌──────────────────────┐
│      Ruby Editor     │
│      Tkinter Text    │
└──────────┬───────────┘
           │
           │ Run
           ▼
┌──────────────────────┐
│   Temporary .rb File │
└──────────┬───────────┘
           │
           │ subprocess.Popen()
           ▼
┌──────────────────────┐
│   Local Ruby Runtime │
└──────────┬───────────┘
           │
       stdout / stderr
           │
           ▼
┌──────────────────────┐
│     Output Queue     │
│  threading + queue   │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  Integrated Terminal │
└──────────────────────┘
```

Rubyインタプリタは独立したプロセスとして実行されます。

Pythonは以下の仕組みを通して、そのプロセスと通信します。

* `subprocess`
* `stdin`
* `stdout`
* `stderr`
* `threading`
* `queue`

プロセスからの出力読み取りはTkinterのメインスレッドとは別に処理されるため、Rubyの実行中もUIの応答性を維持できます。

## 🧠 開発を通して学んだこと

July Ruby IDEは、もともと比較的シンプルなRubyコードランナーとして始まりました。

しかし、インタラクティブな開発環境として動作させるためには、別の種類のエンジニアリング上の問題に取り組む必要がありました。

### コード実行からプロセス管理へ

最初の実行モデルはシンプルでした。

```
Source Code
    ↓
Temporary .rb File
    ↓
Ruby Interpreter
    ↓
Output
```

Rubyコードを実行するには十分でしたが、対話型プログラムには不十分でした。

`gets`、リアルタイム出力、プロセス終了などの機能が必要になると、Rubyインタプリタを単に結果を返すコマンドとしてではなく、**実行中のプロセス**として扱う必要がありました。

その結果、以下のような処理が必要になりました。

* プロセスの生成と終了
* 標準入力による通信
* `stdout` / `stderr` のリアルタイム処理
* バックグラウンドでの出力処理
* ワーカースレッドとTkinter UI間の通信
* プロセス状態と終了処理

これによって、プロジェクトの中心となる問いも変わりました。

> **「このRubyコードを実行できるか？」**

から、

> **「実行中のRubyプログラムを管理し、対話できるか？」**

へと変わったのです。

### 現実の問題から生まれた並行処理

Rubyプロセスは、GUIが応答性を維持する必要がある間にも出力を生成し続けることがあります。

プロセスの出力をTkinterのメインスレッドで直接読み取ると、UIがブロックされる可能性があります。

そのためJuly Ruby IDEでは、バックグラウンドスレッドでプロセスの出力を読み取り、`queue.Queue` を使ってUI側へデータを渡しています。

```
Ruby Process
     ↓
stdout / stderr
     ↓
Background Thread
     ↓
Output Queue
     ↓
Tkinter Main Thread
     ↓
Terminal
```

重要だったのは、単にスレッドの使い方を学んだことではありません。

**アプリケーションに具体的な応答性の問題が発生し、それを解決する必要があったからこそ並行処理を導入した**という点です。

### 「動く」の定義が変わった

このプロジェクトを通して、ソフトウェアが本当に動いているかどうかについての考え方も変わりました。

Rubyプログラムが期待した出力を返すことは、正しさの一部にすぎません。

インタラクティブな開発環境では、さらに以下のことも必要です。

* プログラム実行中もUIが応答する
* 出力された内容をリアルタイムで表示する
* ユーザー入力を受け付ける
* エラーを処理する
* プロセスを停止できる
* ターミナルとプロセスの状態を同期する

つまり、

> **プログラムが正常に実行されることと、アプリケーションが実行中も正しく動作することは同じではありません。**

### 制約から学ぶ

July Ruby IDEでは、言語サーバーやその他の重量級ツールに頼るのではなく、意図的に小さな技術スタックを維持しています。

その結果、いくつかの制限が生まれました。

しかし同時に、内部の実行モデルをより理解しやすくすることもできました。

プロセス管理を抽象化の裏側に隠すのではなく、以下の仕組みを自分で扱う必要がありました。

* OSレベルのプロセス
* 標準ストリーム
* スレッド境界
* UIの応答性
* 一時ソースファイル
* プロセスのライフサイクル

そのため、このプロジェクトは機能豊富なIDEを作ることよりも、その下で動いている仕組みを理解することに重点を置くようになりました。

## 🎯 なぜもう一つRuby IDEを作るのか？

すでに優れたRuby開発環境は数多く存在します。

このプロジェクトは、それらに取って代わることを目的としていません。

目的は、**「Run」を押してからプログラムの出力が表示されるまでに何が起きているのか**を理解することでした。

IDEの裏側に実行プロセスを隠すのではなく、July Ruby IDEではその流れを比較的見える形にしています。

```
Source Code
    ↓
Temporary Ruby File
    ↓
Ruby Process
    ↓
stdin / stdout / stderr
    ↓
Terminal
```

このツールそのものを作ることが、Rubyと開発者向けツールについて学ぶ一部になりました。

## 🎨 設計思想

July Ruby IDEは、意図的に機能の多いIDEになることを避けています。

目標は、

> 「もう一つのRubyMineを作る」

ことではありません。

目標は、

> **「IDEが実際に何をしているのかを理解するために、必要最低限のIDEを作る」**

ことです。

そのため、以下を重視しています。

* 機能数よりもシンプルさ
* 抽象化よりも可視性
* リモートサービスよりもローカル実行
* 本番向けのワークフローよりも実験

プロフェッショナルなRuby開発環境というより、**IDEのようなインターフェースを持ったRuby Playground**に近いものです。

## 🚀 実行方法

### 必要環境

* Windows
* Python 3.x
* Ruby

Rubyがシステムにインストールされている必要があります。

IDEは以下の方法でRuby実行ファイルを自動的に探します。

1. システムの `PATH`

## 📌 制限事項

July Ruby IDEは実験的・教育目的のプロジェクトです。

**プロフェッショナルなRuby開発環境を置き換えることを目的としていません。**

現在の主な制限事項：

* 完全なRubyパーサーではなく、基本的なシンタックスハイライトのみ
* Language Serverベースではない基本的なオートコンプリート
* デバッグインターフェースなし
* プロジェクト管理機能なし
* 統合されたGem管理機能なし
* Ruby Language Serverとの統合なし
* Windowsを前提としたRuby実行ファイルの検出

大規模なRubyプロジェクトでは、VS CodeやRubyMineなどのフル機能の開発環境を推奨します。

## 🧠 Core Insight

July Ruby IDEは、シンプルな問いから始まりました。

> **「Runを押したとき、実際には何が起きているのか？」**

その答えが、小さなソフトウェアプロジェクトになりました。

エディタは表面にすぎません。

その下には、複数のプロセスと仕組みが連なっています。

```
Code
 ↓
Editor
 ↓
Python
 ↓
Operating System
 ↓
Ruby Process
 ↓
stdin / stdout / stderr
 ↓
Terminal
```

この流れを理解することこそが、このプロジェクトの本当の目的です。

さらに、このプロジェクトを通して、制限を単に「制限事項」として記録するのではなく、**調査すべきエンジニアリング上の問題として捉える**ことを学びました。

> **アイデアは始まりにすぎない。エンジニアリングは、それを動かそうとした瞬間から始まる。**
